# Kapitel 16 – GUI (Trin 1): JavaFX-layout og struktur

## 1. Introduktion

Session 16 introducerer grafiske brugergrænseflader (GUI).

Indtil nu har applikationerne fokuseret på:

- domæneobjekter
- responsibility (ansvar)
- persistens
- test
- samarbejde mellem objekter

Session 16 tilføjer:

> grafisk interaktion med brugeren

Fokus er på:

- JavaFX
- GUI-struktur
- scener og vinduer (stages)
- FXML
- kontrolelementer
- containere
- ViewHandler
- applikationsstruktur

Målet er ikke avanceret GUI-programmering.

Målet er:

> at designe GUI-applikationer, samtidig med at objektorienteret responsibility bevares.

---

## 2. Hvad er en GUI?

GUI betyder:

```text
Graphical User Interface
```

Eksempler:

- knapper
- labels
- tekstfelter
- vinduer
- tabeller

GUI-applikationer gør det muligt for brugeren at interagere visuelt.

Eksempel:

```text
+-----------------------+
| Name: [___________]   |
|                       |
| [ OK ]                |
|                       |
| Status message        |
+-----------------------+
```

GUI udgør endnu et lag med responsibility.

Modelobjekterne er fortsat centrale.

---

## 3. GUI-struktur

Session 16 introducerer en GUI-struktur baseret på JavaFX.

Konceptuel struktur:

```text
Main
 ↓

MyApplication
 ↓

ViewHandler
 ↓

FXML
 ↓

Controls
```

Responsibilities holdes adskilt.

GUI-koden bør ikke overtage modellens responsibility.

---

## 4. JavaFX-applikationens struktur

En JavaFX-applikation indeholder typisk:

### Main

Har responsibility for:

- at starte JavaFX

Eksempel:

```java
public class Main
{
  public static void main(String[] args)
  {
    Application.launch(
        MyApplication.class);
  }
}
```

---

### MyApplication

Har responsibility for:

- at starte applikationen
- at oprette visningen

Eksempel:

```java
public class MyApplication
    extends Application
{
  public void start(
      Stage primaryStage)
  {
    ViewHandler view =
        new ViewHandler();

    view.start(primaryStage);
  }
}
```

---

### ViewHandler

Har responsibility for:

- at indlæse visninger
- at oprette scener
- at åbne vinduer
- senere at skifte mellem vinduer

Responsibility er fortsat klart afgrænset.

---

## 5. Stage

JavaFX introducerer:

```text
Stage
```

Et `Stage` repræsenterer:

> et vindue

Eksempel:

```text
+-----------------------+
| My Window             |
|                       |
| GUI content           |
|                       |
+-----------------------+
```

Et `Stage` styrer:

- titel
- bredde
- højde
- synlighed

Eksempel:

```java
primaryStage.setTitle(title);
```

```java
primaryStage.show();
```

---

## 6. Scene

JavaFX introducerer:

```text
Scene
```

En `Scene` repræsenterer:

> GUI-indholdet i et vindue

Eksempel:

```text
Stage
 └── Scene
      └── GUI-komponenter
```

Eksempel:

```java
Scene currentScene;
```

`Scene` administrerer GUI-elementerne.

---

## 7. Scene Graph

JavaFXs GUI-elementer danner et hierarki.

Eksempel:

```text
VBox
├── TextField
└── HBox
     ├── Button
     └── Label
```

Dette hierarki kaldes:

```text
Scene Graph
```

GUI-design bliver dermed et samarbejde mellem objekter.

Objekter indeholder andre objekter.

---

## 8. FXML

FXML beskriver GUI-strukturen.

Eksempel:

```xml
<VBox>

  <children>

    <TextField/>

    <Button text="OK"/>

  </children>

</VBox>
```

FXML beskriver:

- kontrolelementer
- layout
- hierarki

FXML adskiller:

```text
GUI-struktur
```

fra:

```text
Java-implementering
```

Dette understøtter adskillelse af responsibility.

---

## 9. Kontrolelementer

Kontrolelementer er GUI-komponenter, som brugeren interagerer med.

Eksempler:

```text
Button
```

```text
TextField
```

```text
Label
```

Eksempel:

```xml
<Button text="OK"/>
```

Eksempel:

```xml
<TextField/>
```

Kontrolelementer gør interaktion mulig.

---

## 10. Containere

Containere organiserer kontrolelementer.

Eksempler:

### VBox

Placerer elementer lodret.

Eksempel:

```text
Button

TextField

Label
```

---

### HBox

Placerer elementer vandret.

Eksempel:

```text
Button  Label
```

Containere hjælper med at organisere layoutet.

---

## 11. Rodnode

FXML begynder med ét rodelement.

Eksempel:

```xml
<VBox>

</VBox>
```

Rodnoden bliver:

> den øverste GUI-container

Alt hører til inde i rodnoden.

Eksempel:

```text
VBox
├── Button
├── Label
└── TextField
```

GUI-strukturen bliver hierarkisk.

---

## 12. Indlæsning af FXML

ViewHandler indlæser FXML.

Eksempel:

```java
FXMLLoader loader =
    new FXMLLoader();

loader.setLocation(
    getClass()
    .getResource(fxmlFile));

root = loader.load();
```

Responsibility:

```text
FXML-fil
→ GUI-objekthierarki
```

ViewHandler opretter GUI-objekterne.

---

## 13. Vinduestitel

FXML-rodnoder kan indeholde:

```xml
userData="Simple GUI"
```

Eksempel:

```xml
<VBox
 userData="Simple GUI">
```

Senere:

```java
root.getUserData()
```

Vinduets titel bliver:

```text
Simple GUI
```

Responsibility forbliver samlet ét sted.

---

## 14. Bredde og højde

FXML kan angive dimensioner.

Eksempel:

```xml
prefWidth="250"
```

Eksempel:

```xml
prefHeight="115"
```

ViewHandler anvender dimensionerne.

Eksempel:

```java
primaryStage.setWidth(
    root.getPrefWidth());

primaryStage.setHeight(
    root.getPrefHeight());
```

GUI-strukturen styrer udseendet.

---

## 15. CSS-styling

JavaFX understøtter CSS.

Eksempel:

```css
.label
{
  -fx-text-fill: red;

  -fx-font-weight: bold;

  -fx-font-size: 20px;
}
```

FXML:

```xml
<stylesheets>

<String fx:value=
"View1.css"/>

</stylesheets>
```

CSS adskiller:

```text
Udseende
```

fra:

```text
Behavior
```

Responsibilities holdes adskilt.

---

## 16. Responsibility i GUI

God responsibility:

Model:

```text
Forretningslogik
```

GUI:

```text
Præsentation
```

Mindre god løsning:

```text
GUI beregner domænelogik
```

Bedre løsning:

```text
GUI spørger modellen
```

Eksempel:

Mindre god løsning:

```java
buttonPressed()
{
  // calculate grades
}
```

Bedre løsning:

```java
buttonPressed()
{
  gradeList.getAverage();
}
```

Responsibility er fortsat det centrale princip.

## 17. Typiske begynderfejl

Almindelige fejl:

1. At blande GUI- og modellogik.

5. At glemme rodnoden.
6. At forveksle `Stage` og `Scene`.
7. At placere alting i én klasse.
