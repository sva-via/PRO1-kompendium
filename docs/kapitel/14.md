# Kapitel 14 – Interfaces

## 1. Introduktion

Session 14 introducerer interfaces.

Nedarvning introducerede:

> "is-a"

-relationer.

Interfaces introducerer en anden vigtig designmekanisme:

> abstraction gennem kontrakter

Interfaces hjælper objekter med at samarbejde, samtidig med at de reducerer coupling (kobling) mellem klasser.

Fokus er på:

- interfaces
- kontrakter
- abstraction
- løs coupling
- udskiftning af implementationer
- responsibility (ansvar)
- applikationsstruktur

Interfaces er et vigtigt værktøj til at designe objektorienterede systemer, der er lette at vedligeholde.

---

## 2. Hvad er et interface?

Et interface beskriver:

> hvad et objekt kan gøre

uden at beskrive:

> hvordan det gør det

Eksempel:

```java
public interface Model
{
  Customer getCustomer(String phone);

  Vehicle getVehicle(
      String registrationNumber);

  void reserve(
      Vehicle vehicle,
      Customer customer,
      LocalDate from,
      LocalDate to);
}
```

Interfacet angiver:

- metodenavne
- parametre
- returtyper

Implementeringen kommer senere.

---

## 3. Interface som kontrakt

Et interface er en kontrakt.

Eksempel:

```text
Model
```

Kontrakten siger:

```text
Objekter, der implementerer Model,
skal levere disse metoder.
```

Brugere af interfacet behøver kun at vide:

- hvilke metoder der findes
- hvad metoderne gør

Ikke:

- den interne implementering
- datastrukturer
- detaljer om lagring

---

## 4. Implementering af et interface

Klasser implementerer interfaces.

Eksempel:

```java
public class ModelManager
    implements Model
{
}
```

Nøgleordet:

```java
implements
```

betyder:

> ModelManager er et Model

Klassen lover at implementere alle metoder.

---

## 5. Eksempel på implementering

Interface:

```java
public interface Model
{
  Customer getCustomer(
      String phone);
}
```

Implementering:

```java
public class ModelManager
    implements Model
{
  @Override
  public Customer getCustomer(
      String phone)
  {
    // implementation
  }
}
```

Interfacet angiver responsibility.

Den implementerende klasse udfører arbejdet.

---

## 6. @Override

Eksempel:

```java
@Override
public Customer getCustomer(
    String phone)
{
}
```

`@Override` fortæller Java:

> Denne metode implementerer eller overskriver en anden metode.

Fordele:

- opdager stavefejl
- forbedrer læsbarheden
- tydeliggør hensigten

Brug `@Override` konsekvent.

---

## 7. Interfacemetoder

Metoder i et interface er pr. definition:

```text
public
abstract
```

Eksempel:

```java
public interface Model
{
  Vehicle getVehicle(
      String registrationNumber);
}
```

Ingen metodekrop:

```java
{
}
```

Ingen implementering.

Kun en specifikation.

---

## 8. Abstraction

Interfaces understøtter abstraction.

Eksempel:

View:

```text
Har brug for kundedata
```

View bør ikke kende til:

- filer
- databaser
- samlinger
- modellens interne struktur

View har kun brug for:

```text
Model
```

Abstraction via interfaces skjuler implementeringsdetaljer.

---

## 9. Løs coupling

Interfaces reducerer coupling.

Uden interface:

```text
View
 ↓
ModelManager
```

Stærk afhængighed.

Med interface:

```text
View
 ↓
Model
 ↓
ModelManager
```

View afhænger kun af:

```text
Model
```

og ikke af:

```text
ModelManager
```

Løs coupling forbedrer vedligeholdelsen.

---

## 10. Udskiftning af implementationer

Eksempel:

Version 1:

```text
TextFilePersistence
```

Version 2:

```text
JsonPersistence
```

Version 3:

```text
DatabasePersistence
```

Hvis alle implementerer:

```text
Persistence
```

kan resten af systemet forblive uændret.

Interfaces gør det lettere at udskifte implementationer.

---

## 11. Applikationsstruktur

Eksempel på en konceptuel struktur:

```text
View
 ↓
Model Interface
 ↓
ModelManager
 ↓
Persistence Interface
 ↓
Persistence Implementation
```

Responsibilities:

### View

Har responsibility for:

- præsentation af data
- brugerinteraktion

---

### Model Interface

Har responsibility for:

- kontrakten
- at stille de nødvendige operationer til rådighed

---

### ModelManager

Har responsibility for:

- koordinering af modellen
- opdatering af objekter
- synkronisering

---

### Persistence Interface

Har responsibility for:

- kontrakten for lagring
- kontrakten for indlæsning

---

### Persistence Implementation

Har responsibility for:

- den faktiske filhåndtering
- konvertering
- lagringsformat

Responsibility er fortsat et centralt princip.

---

## 12. Interface og responsibility

Godt design:

```text
View
```

kender:

```text
Model
```

Ikke:

```text
TextFilePersistence
```

Godt design adskiller responsibilities.

Objekter bør kun kende det, de har brug for.

---

## 13. Flere interfaces

Java tillader:

```java
extends
```

kun én gang.

Eksempel:

Gyldigt:

```java
class Car
    extends Vehicle
```

Ugyldigt:

```java
class Car
    extends Vehicle,
            Product
```

Java understøtter kun enkelt nedarvning.

Interfaces løser denne begrænsning.

Eksempel:

```java
public class ModelManager
    implements Model,
               Persistence
{
}
```

En klasse kan implementere flere interfaces.

---

## 14. Interface kontra nedarvning

Nedarvning:

```text
is-a
```

Eksempel:

```text
Car is a Vehicle
```

Interface:

```text
can-do
```

Eksempel:

```text
ModelManager implements Model
```

Nedarvning bruges til:

- specialisering

Interfaces bruges til:

- funktionalitet
- abstraction
- kontrakter

Begge mekanismer er vigtige.

---

## 15. Eksempel: Persistence-interface

Eksempel:

```java
public interface Persistence
{
  void save();

  void load();
}
```

Implementering:

```java
public class TextFilePersistence
    implements Persistence
{
}
```

Alternativ:

```java
public class JsonPersistence
    implements Persistence
{
}
```

Resten af systemet forbliver uændret.

---

## 16. Hvorfor bruge interfaces?

Fordele:

- abstraction
- løs coupling
- lettere vedligeholdelse
- lettere udskiftning af implementationer
- tydeligere responsibility
- bedre arkitektur

Interfaces understøtter et skalerbart design.

---

## 17. Test med interfaces

Interfaces gør test lettere.

Eksempel:

Reference:

```java
Model model;
```

Mulig implementering:

```java
ModelManager
```

Alternativ testimplementering:

```java
FakeModel
```

Interfaces gør det lettere at isolere og teste systemer.

---

## 18. Typiske begynderfejl

Almindelige fejl:

1. At forveksle nedarvning og interfaces.
2. At placere implementering i interfaces.
3. At bryde grænserne for responsibility.
4. At oprette unødvendige interfaces.
5. At skabe tæt coupling til implementeringsklasser.
6. At glemme `implements`.
7. At glemme at implementere de nødvendige metoder.
