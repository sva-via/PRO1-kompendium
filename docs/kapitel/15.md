# Kapitel 15 – Persistens

## 1. Introduktion

Session 15 introducerer persistens.

Persistens betyder:

> at gemme data, så de kan indlæses igen senere.

Indtil nu har objekter kun eksisteret, mens programmet kørte.

Når programmet lukkes:

```text
Objekterne forsvinder
```

Persistens gør det muligt for objekter at eksistere ud over programmets kørsel.

Fokus er på:

- persistens
- lagring af objekter
- indlæsning af objekter
- filformater
- exceptions
- interfaces
- adskillelse af responsibility (ansvar)
- JSON-persistens

Persistens bliver en vigtig del af udviklingen af realistiske applikationer.

---

## 2. Hvad er persistens?

Persistens betyder permanent lagring af data.

Eksempel:

```text
Notebook-applikation
```

Uden persistens:

```text
Programmet lukkes
→ Noterne forsvinder
```

Med persistens:

```text
Programmet lukkes
→ Noterne gemmes i en fil
→ Noterne indlæses næste gang
```

Persistens giver applikationen hukommelse.

---

## 3. Responsibility og persistens

Objekter skal fortsat have en klar responsibility.

Eksempel:

```text
Notebook
```

Har responsibility for:

- noter
- tilføjelse af noter
- fjernelse af noter

Har ikke responsibility for:

- læsning af filer
- skrivning af filer

Lagring hører hjemme et andet sted.

God objektorienteret design adskiller responsibilities.

---

## 4. Persistence-interface

Eksempel:

```java
public interface NotebookPersistence
{
  void save(Notebook notebook);

  Notebook load();
}
```

Interfacet beskriver:

- hvad persistens kan gøre

Ikke:

- hvordan persistens fungerer

Interfaces understøtter abstraction.

---

## 5. Eksempel på implementering

Eksempel:

```java
public class
JsonFileNotebookPersistence
    implements NotebookPersistence
{
}
```

Nøgleordet:

```java
implements
```

betyder:

> Denne klasse opfylder persistence-kontrakten.

Implementeringen håndterer:

- læsning af filer
- skrivning af filer
- konvertering

Modellen forbliver adskilt.

---

## 6. Lagring af data

Eksempel:

```java
@Override
public void save(Notebook notebook)
{
  try
  {
    parser.toJsonFile(
        notebook,
        fileName);
  }
  catch (ParserException e)
  {
    throw new PersistenceException(
        "Could not save notebook", e);
  }
}
```

Responsibility:

```text
Objekt → fil
```

Selve `Notebook` ændres ikke.

---

## 7. Indlæsning af data

Eksempel:

```java
@Override
public Notebook load()
{
  try
  {
    Notebook notebook =
        parser.fromJsonFile(
            fileName,
            Notebook.class);

    return notebook;
  }
  catch (ParserException e)
  {
    throw new PersistenceException(
        "Could not load notebook", e);
  }
}
```

Responsibility:

```text
Fil → objekt
```

Persistens genskaber objektets state.

---

## 8. JSON-format

JSON står for:

```text
JavaScript Object Notation
```

Eksempel:

```json
{
  "notes":
  [
    {
      "note":"Check Facebook",
      "highPriority":false
    },
    {
      "note":"Make PRO1 exercises",
      "highPriority":true
    }
  ]
}
```

JSON er:

- struktureret
- læsbart
- udbredt

JSON er ofte velegnet til persistens af objekter.

---

## 9. JSON og objekter

Objekter bliver til strukturerede data i en fil.

Eksempel på objekt:

```text
PriorityNote
```

Felter:

```text
note
highPriority
```

JSON:

```json
{
  "note":"Check Facebook",
  "highPriority":false
}
```

Persistens konverterer:

```text
Objekt → JSON
```

og senere:

```text
JSON → Objekt
```

---

## 10. Exceptions og persistens

Filoperationer kan mislykkes.

Eksempler:

- filen findes ikke
- ugyldigt filformat
- problemer med parseren

Persistens skal kommunikere problemer tydeligt.

Eksempel:

```java
throw new PersistenceException(
    "Could not load notebook", e);
```

Responsibility:

```text
Opdag problemer
→ Kommunikér problemer
```

Exceptions er fortsat vigtige.

---

## 11. Test af persistens

Persistens bør testes.

Eksempel:

```java
@Test
void testJsonParserPersistence()
{
  Notebook notebook =
      createNotebook();

  NotebookPersistence
      persistence =
      new JsonFileNotebookPersistence(
          "notebook.json");

  assertDoesNotThrow(
      () -> persistence.save(notebook));

  Notebook loaded =
      assertDoesNotThrow(
          () -> persistence.load());

  checkValidLoadedNotebook(
      notebook, loaded);
}
```

Tests kontrollerer:

- at lagring virker
- at indlæsning virker
- at data bevares korrekt

Persistens kræver test.

---

## 12. Filformater

Der findes forskellige tilgange til persistens.

---

### Tekstfil

Eksempel:

```text
Bob;3;bob@email.com
```

Fordele:

- enkel
- læsbar
- let at redigere

Ulemper:

- manuel parsing
- større vedligeholdelsesarbejde

---

### Binær fil

Fordele:

- automatisk lagring af objekter

Ulemper:

- svær at inspicere
- ændringer i klasser kan bryde kompatibiliteten

---

### JSON

Fordele:

- læsbart
- struktureret
- understøttes af biblioteker
- let at integrere med andre systemer

Ulemper:

- kan afsløre implementeringsdetaljer

Valget afhænger af responsibility og krav.

---

## 13. Persistens og interfaces

Godt design:

```text
Applikation
 ↓
Persistence Interface
 ↓
JsonPersistence
```

Senere:

```text
Applikation
 ↓
Persistence Interface
 ↓
DatabasePersistence
```

Applikationen forbliver uændret.

Interfaces reducerer coupling.

---

## 14. Persistens og nedarvning

Nedarvning introducerer ekstra kompleksitet.

Eksempel:

`Vehicle`-hierarki:

```text
Vehicle
├── Car
└── Bicycle
```

JSON:

```json
{
 "owner":"Bob",
 "price":200,
 "regNo":"AB12345"
}
```

Problem:

Ved indlæsning:

```text
Parseren ser kun Vehicle
```

Hvilken underklasse skal oprettes?

Persistens skal bevare typeinformation.

---

## 15. Polymorf persistens

Eksempel:

```java
parser.registerPolymorphicAdapter(
    Vehicle.class,
    List.of(
       Car.class,
       Bicycle.class));
```

Parseren lærer:

```text
Vehicle kan være:

Car
Bicycle
```

Typeinformation bliver vigtig.

---

## 16. Ekstra information i JSON

Eksempel:

```json
{
 "owner":"Bob",
 "price":200,
 "class-type":"Car"
}
```

Nu kan indlæsningen genskabe:

```text
Vehicle → Car
```

Persistens kræver nogle gange ekstra information.

---

## 17. Adskillelse af responsibility

Godt design:

`Notebook`:

```text
Administrerer noter
```

Persistens:

```text
Administrerer filer
```

Parser:

```text
Konverterer formater
```

Responsibility er fortsat et centralt princip.

Objekter bør gøre én ting godt.

---

## 18. Typiske begynderfejl

Almindelige fejl:

1. At blande persistens ind i modelklasser.
2. At glemme exception-håndtering.
3. At gemme unødvendige implementeringsdetaljer.
4. At bryde grænserne for responsibility.
5. At glemme at teste persistens.
6. At ignorere kompleksiteten ved nedarvning.
7. At skabe tæt coupling til et bestemt filformat.
