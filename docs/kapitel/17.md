# Kapitel 17 – GUI (Trin 2): Data og hændelser

## 1. Introduktion

Session 17 fortsætter udviklingen af GUI-applikationer.

Session 16 introducerede:

- JavaFX-struktur
- `Stage`
- `Scene`
- FXML
- kontrolelementer
- containere
- ViewHandler

Session 17 tilføjer:

> interaktion

GUI-applikationer bliver nyttige, når brugeren kan:

- trykke på knapper
- indtaste data
- opdatere visninger
- hente information fra modellen
- navigere mellem vinduer

Fokus er på:

- hændelser
- ViewController-klasser
- adgang til modeldata
- `TableView`
- flere vinduer
- responsibility (ansvar) i GUI

Målet er:

> at forbinde GUI-interaktion med modellens responsibility.

---

## 2. Hændelser

En hændelse opstår, når brugeren interagerer med GUI'en.

Eksempler:

- klik på en knap
- indtastning af tekst
- valg af data

Eksempel:

```text
Bruger trykker på en knap
↓
GUI-hændelse opstår
↓
Controller-metode udføres
```

Hændelser gør applikationer interaktive.

---

## 3. ViewController-klasser

Session 17 introducerer:

```text
ViewController
```

Har responsibility for:

- at modtage GUI-hændelser
- at kommunikere med modellen
- at opdatere GUI-komponenter

Eksempel på struktur:

```text
FXML-fil
↓
ViewController
↓
Model
```

Én controller har normalt responsibility for én FXML-fil.

Eksempel:

```text
SimpleGUI.fxml
↓
SimpleGUIController
```

Responsibilities holdes adskilt.

---

## 4. Forbindelsen mellem FXML og Controller

FXML forbinder GUI og controller.

Eksempel:

```xml
fx:controller=
"SimpleGUIController"
```

Betyder:

> denne GUI bruger denne controllerklasse

FXML beskriver:

```text
Layout
```

Controller implementerer:

```text
Behavior
```

Responsibilities holdes adskilt.

---

## 5. fx:id

GUI-kontrolelementer kan få identifikatorer.

Eksempel:

```xml
<TextField
 fx:id="inputField"/>
```

Eksempel:

```xml
<Label
 fx:id="label"/>
```

Controlleren får adgang til kontrolelementerne via deres identifikatorer.

Eksempel:

```java
private TextField inputField;

private Label label;
```

Controlleren kan nu:

- læse værdier
- opdatere værdier

---

## 6. Hændelsesmetoder

FXML forbinder kontrolelementer med metoder.

Eksempel:

```xml
<Button
 onAction=
 "#buttonPressed"/>
```

Betyder:

> kald metoden:

```java
buttonPressed()
```

når der trykkes på knappen.

Eksempel på forløb:

```text
Tryk på knap
↓
Hændelse opstår
↓
buttonPressed()
↓
Opdatér GUI
```

Hændelser forbinder interaktion og behavior.

---

## 7. Controllerens responsibility

God responsibility:

Controller:

```text
Læser værdier fra GUI
```

Controller:

```text
Spørger modellen
```

Controller:

```text
Opdaterer GUI
```

Mindre god løsning:

```text
Controller udfører domænelogik
```

Eksempel:

Mindre god løsning:

```java
buttonPressed()
{
  // calculate reservations
}
```

Bedre løsning:

```java
buttonPressed()
{
  model.reserve(...);
}
```

Modellen har fortsat responsibility.

---

## 8. Adgang til modeldata

GUI bør få adgang til modeldata gennem modellens responsibility.

Eksempel på spørgsmål:

```text
Hvem opretter en reservation?
```

Modellen.

---

```text
Hvem ved, hvilke køretøjer der er ledige?
```

Modellen.

---

```text
Hvem finder kunder?
```

Modellen.

GUI'en bør spørge:

```java
model.getCustomer(phone)
```

Ikke:

```java
// GUI søger selv efter kunder
```

Responsibility er fortsat det centrale princip.

---

## 9. Model-interface

Session 14 introducerede interfaces.

GUI'en bør anvende:

```text
Model-interface
```

Eksempel:

```java
Customer getCustomer(
    String phone);
```

Eksempel:

```java
Vehicle getVehicle(
    String registrationNumber);
```

Controlleren afhænger af:

```text
Model
```

ikke af:

```text
ModelManager
```

Løs coupling (kobling) er fortsat vigtig.

---

## 10. Eksempel på hændelsesforløb

Konceptuelt forløb:

```text
Der trykkes på en knap
↓
Controller modtager hændelsen
↓
Controller læser input
↓
Controller spørger modellen
↓
Modellen opdaterer objekter
↓
Controller opdaterer GUI
```

Eksempel:

```text
Kundens telefonnummer indtastes
↓
Der trykkes på søgeknappen
↓
model.getCustomer(phone)
↓
Vis kundens navn
```

GUI'en koordinerer.

Modellen har fortsat responsibility.

## 11. TableView

Session 17 introducerer:

```text
TableView
```

`TableView` viser samlinger visuelt.

Eksempel:

```text
+----------------------+
| Name    | Grade      |
+----------------------+
| Ann     | 12         |
| Bob     | 7          |
| Carl    | 10         |
+----------------------+
```

`TableView` viser ofte:

- samlinger fra modellen
- søgeresultater
- lister af objekter

GUI'en står for præsentationen.

Modellen står for lagringen.

## 13. Én controller pr. vindue

Anbefalet struktur:

```text
ReservationView.fxml
↓
ReservationViewController
```

Eksempel:

```text

↓
CustomerViewController
```

Responsibility er lokaliseret.

Undgå:

```text
Én controller håndterer hele applikationen
```

Små responsibilities giver et bedre design.

---

## 14. Adskillelse af GUI og model

God struktur:

```text
GUI
↓
Controller
↓
Model Interface
↓
ModelManager
↓
Modelobjekter
```

En god opdeling forbedrer:

- læsbarhed
- vedligeholdelse
- testbarhed

Objektorienteret responsibility er fortsat vigtig.

---

## 15. Hændelser og samarbejde mellem objekter

Objekter samarbejder.

Controller:

```text
Modtager hændelser
```

Model:

```text
Opdaterer state
```

GUI:

```text
Viser state
```

Intet enkelt objekt bør gøre alting.

Samarbejde er fortsat centralt.

---

## 16. Typiske begynderfejl

Almindelige fejl:

1. At placere domænelogik i controlleren.
2. At gøre controllerne for store.
3. At få direkte adgang til modellens interne struktur.
4. At ignorere interfaces.
5. At lade én controller styre alting.
6. At lade GUI'en selv søge i samlinger.
7. At blande GUI-responsibility og domæneresponsibility.

## Opsummering

Session 17 introducerer GUI-interaktion.

Vigtige idéer omfatter:

- hændelser skaber interaktion
- controllere modtager hændelser
- controllere kommunikerer med modellen
- GUI'en bør ikke implementere domænelogik
- `fx:id` forbinder kontrolelementer og controller
- `onAction` forbinder hændelser og metoder
- `TableView` viser samlinger
- ViewHandler koordinerer vinduer
- responsibility er fortsat et centralt princip

GUI-applikationer bliver nyttige, når interaktion og objektorienteret responsibility arbejder sammen.
